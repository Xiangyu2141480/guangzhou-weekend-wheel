## 主要来源与取舍

对基线临时启用 source map 后，按生成代码映射区间估算：React、React DOM 和
scheduler 约占 190 KB，常驻池约占 137 KB，其余应用代码约占 42 KB。
此处是定位用途的近似归因，精确验收以普通生产构建的文件字节数为准。

广州旧版 core 是最大的单个业务数据模块，重复保存字段名，再通过 spread 和 map
补齐公共字段。其他城市已使用共享工厂，但仍重复携带大量时长和交通模板文字。

本次调整：

- 将广州原有 61 条 core seed 改为与其他常驻数据类似的紧凑工厂调用，共用字段名。
  保留独立的旧版预算文案、时段判定及 ID 迁移规则，避免与新数据工厂的细微差异混用。
- 将 349 处重复时长改为共享字符串；327 处地铁说明改为共享模板。默认接驳文案、
  空接驳文案、换乘提示和支线名称按原文重建。
- 五城模块继续只定义各自的数据；共享模块仅包含时长和交通文字模板，不包含活动记录。

当前常驻池是同步加载的，城市切换立即得到该城的离线 fallback；旧广州收藏也同步
读取广州池以完成 ID 映射。简单使用 `manualChunks` 或 `import()` 不会减少预算统计的
全部 JS 总量；按城市真正延迟加载则需要处理异步状态、失败恢复和收藏迁移。本次保留
加载行为，通过减少实际重复代码释放空间，不引入额外网络依赖。Result/Favorites 等
组件规模较小，继续拆分只会增加请求与异步交互的复杂度。

## 内容与回归验证

优化前将 `getAllEvergreenActivities()` 的完整输出保存在仓库外的本地临时文件，
优化后对序列化输出进行深度比较，357 项记录逐字段一致。比较覆盖 ID、legacyIds、
顺序、城市、行政区、分类、费用、时段、标签、推荐理由、提醒、地图及交通。
北京、上海、深圳、苏州各 40 项，广州 197 项。

新增单测覆盖地铁默认/自定义/空接驳及广州旧数据的价格、迁移元数据和时段规则。
现有浏览器回归覆盖城市选择与持久化、切城重置与数据隔离、五城筛选、换批、转盘、
结果与收藏、旧收藏迁移、快照异常降级、多视口、键盘和无障碍。

官方实时来源适配器、已提交的快照、缓存策略、同步工作流和前端功能代码均未修改。

优化源码生成相同的 JS 文件（352,725 字节），故上述收益来自数据表示优化。

## 限制与回滚

本次没有改变首屏仍携带五城数据的事实，也没有移除任何活动。后续扩容仍需运行
全量预算检查；17,275 字节是当前构建余量，不是未来内容规模的保证。

如需回滚，通过独立 PR revert 数据优化提交并运行上述验证。Vite 审计补丁独立提交，
可保留；不要提高预算、修改来源适配器或恢复到不通过审计的依赖来绕过门禁。
